# 两台 Quest 独立运行

需要：两台 Quest（已开开发者模式）、一台电脑、三者连同一个 Wi-Fi。电脑负责跑中转和调用 OpenAI，头显里不放 key。

## 安装（每台头显做一次）

1. 用 USB 线只连 **A 头显**，戴上头显，在弹窗里点"允许 USB 调试"。
2. 双击 `Install-A.cmd`，等到出现 `Installed`。
3. 拔掉 A，只连 **B 头显**，同样允许 USB 调试，双击 `Install-B.cmd`。

两个应用装在头显应用库的"未知来源"里，名字是 `Mystery Sort A` 和 `Mystery Sort B`。

## 每次运行

1. 电脑上双击上一级文件夹的 `03-Start-Relay-For-Quest.cmd`。窗口会列出本机 IP，并显示 `OpenAI: enabled`。保持窗口开着。
2. Windows 第一次会弹防火墙提示，勾选当前网络并允许。
3. 两台头显分别打开 `Mystery Sort B` 和 `Mystery Sort A`，先后顺序不限。
4. 后墙上的状态文字从 `Looking for the relay PC on this Wi-Fi...` 变成 `Relay 192.168.x.x` 就是连上了。中转窗口会打印 `[peer] room=A` 和 `[peer] room=B`。

## A 怎么操作

站在三块面板前，用右手：

- **手柄**：射线指向便利贴，按住食指扳机拖动，在分组面板上松开。
- **手势**（放下手柄后）：手的指针射线指向便利贴，食指拇指捏住拖动，松开放下。

射线指到便利贴时，线索全文显示在线索托盘上方。后墙第三行会提示当前识别到的是手柄还是手。

## B 看什么

B 站在房间后部，看化身在线索墙和两侧面板之间走动、拿放。后墙黄字是动作和 AI 的解读。

## 连不上时

- **一直是 Looking for the relay**：多半是 Wi-Fi 隔离了设备间的广播（校园网、访客网常见）。换手机热点或自己的路由器。
- **广播被挡但设备能互通**：在头显里手动指定电脑 IP。电脑上运行（把 IP 换成中转窗口显示的地址，A、B 各执行一次，包名末尾分别是 `a` 和 `b`）：
  `adb shell "echo 192.168.x.x > /sdcard/Android/data/com.localvr.mysterysort.a/files/relay.txt"`
  然后重启应用。
- **A 连上了但 B 的化身不动**：看中转窗口有没有 `[peer] room=B`。没有就是 B 的包到不了电脑，检查防火墙是否放行了 python 的 UDP 9000。

## 没验证过的部分

这两个 APK 只做过构建和安装包检查（包名、ARM64、网络和手部追踪权限）。**没有在头显里运行过**。以下都需要你实测：

- 头显内画面、站位和文字大小是否合适。
- 手柄扳机和手势捏合的抓放是否顺手。
- 两台头显通过广播找到中转。

同一套逻辑的桌面版（鼠标输入、本机三进程）是自动跑通的，网络协议和 AI 部分和头显版用的是同一份代码。
