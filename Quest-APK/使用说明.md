# 两台 Quest 独立运行

需要：两台 Quest（已开开发者模式）、一台电脑、三者连同一个 Wi-Fi。电脑负责跑中转和调用 OpenAI，头显里不放 key。

## 安装（每台头显做一次）

1. 用 USB 线只连 **A 头显**，戴上头显，在弹窗里点"允许 USB 调试"。
2. 双击 `Install-A.cmd`，等到出现 `Installed`。
3. 拔掉 A，只连 **B 头显**，同样允许 USB 调试，双击 `Install-B.cmd`。

两个应用装在头显应用库的"未知来源"里，名字是 `Mystery Sort A` 和 `Mystery Sort B`。

MR 透视版用 `Install-MR-A.cmd` 和 `Install-MR-B.cmd` 安装，名字是 `Mystery Sort MR A` 和 `Mystery Sort MR B`。VR 版和 MR 版是四个独立的应用，可以同时装在一台头显上。同一台头显上 VR 版和 MR 版不要同时开着，它们占同一个端口。VR 版和 MR 版的协议相同，A 用 VR 版、B 用 MR 版也能连。

电脑上已连着头显时也可以不戴头显直接启动，包名是 `com.localvr.mysterysort.a`、`.b`、`.mra`、`.mrb`：
`adb shell monkey -p com.localvr.mysterysort.mrb -c android.intent.category.LAUNCHER 1`

## 每次运行

1. 电脑上双击上一级文件夹的 `03-Start-Relay-For-Quest.cmd`。窗口会列出本机 IP，并显示 `OpenAI: enabled`。保持窗口开着。
2. Windows 第一次会弹防火墙提示，勾选当前网络并允许。
3. 两台头显分别打开 `Mystery Sort B` 和 `Mystery Sort A`，先后顺序不限。
4. 后墙上的状态文字从 `Looking for the relay PC on this Wi-Fi...` 变成 `Relay 192.168.x.x` 就是连上了。中转窗口会打印 `[peer] room=A` 和 `[peer] room=B`。

## A 怎么操作

站在三块面板前，用右手：

- **手柄**：射线指向便利贴，按住食指扳机拖动，在分组面板上松开。
- **手势**（放下手柄后）：手的指针射线指向便利贴，食指拇指捏住拖动，松开放下。

射线指到便利贴时，线索全文显示在线索托盘上方。后墙第三行会提示当前识别到的是手柄还是手。

## B 看什么

B 站在房间后部，看化身在线索墙和两侧面板之间走动、拿放。后墙黄字是动作和 AI 的解读。

## MR 透视版

MR 版里看到的是真实房间，面板、便利贴和化身叠在上面。

**站位**。面板位置以重新定位时的站位和朝向为准。B 需要前方约 3 × 3 米的空地：站到空地一端、面朝空地，长按右手柄 Meta 键重新定位。线索墙在正前方 3 米，两块分组面板在左右前方约 1.5 米，化身站在前方 1.8 米。A 的三块面板在面前 1.2 米处一字排开，适合站在桌前或空处。

**挪面板**（A、B 都可以，只用右手柄）：

- 射线指着面板，按住握键（中指键）抓起，面板跟着射线走并自动转向你。
- 抓着时前后推摇杆，把面板推远或拉近。
- 长按 B 键 2 秒，所有面板回到默认位置。
- 面板位置保存在头显里，下次启动还在原处。VR 版和 MR 版各存一份。

A 拖便利贴的操作不变。状态文字在第一块面板的下方，线索全文（A）和 AI 字幕（B）在它上方，都跟着面板走。化身脚下有一块圆形假阴影，用来在真实地面上显得站得住。

化身不识别真实家具。它在面板之间走直线，路上有桌椅会穿过去，所以 B 的面板要摆在空地周围。

## 连不上时

- **一直是 Looking for the relay**：先看电脑是否还连着和头显相同的 Wi-Fi。电脑同时插着网线时，Windows 有时会把 Wi-Fi 断开，电脑只剩有线网，头显就收不到中转的广播。重新连上 Wi-Fi 后几秒内会自动恢复，中转和应用都不用重启。
- **电脑 Wi-Fi 正常但仍然找不到**：多半是 Wi-Fi 隔离了设备间的广播（校园网、访客网常见）。换手机热点或自己的路由器。
- **广播被挡但设备能互通**：在头显里手动指定电脑 IP。电脑上运行（把 IP 换成中转窗口显示的地址，A、B 各执行一次，包名末尾分别是 `a` 和 `b`）：
  `adb shell "echo 192.168.x.x > /sdcard/Android/data/com.localvr.mysterysort.a/files/relay.txt"`
  然后重启应用。
- **A 连上了但 B 的化身不动**：看中转窗口有没有 `[peer] room=B`。没有就是 B 的包到不了电脑，检查防火墙是否放行了 python 的 UDP 9000。

## 已验证和未验证

- **VR 版**：两台 Quest Pro 在实验室 Wi-Fi 上通过广播找到中转，A 用手柄拖放，B 的化身跟随，实测可用。手势捏合没有专门测过。
- **MR 版**：两台 Quest Pro 上安装并启动，系统日志确认透视开启，A 的拖放经中转翻译后发到 B。头显内的画面效果、挪面板的手感、假阴影的观感还没有逐项确认。启动时日志里有两条 `GL_INVALID_VALUE`，目前没有看到影响；透视画面出现黑块或闪烁时先查这里。

同一套逻辑的桌面版（鼠标输入、本机三进程）是自动跑通的，网络协议和 AI 部分和头显版用的是同一份代码。
