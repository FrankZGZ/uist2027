# Mystery Sort：两个房间、两个化身的混合现实协作归类

两个人分别在两个不同的房间里，戴着 Quest 头显，一起把六张谋杀谜题的线索便利贴归成两组。每个房间的布置不一样：A 的面板竖直挂在墙上，B 的垫子平铺在桌上。一个人在自己房间里拿放便利贴，对方房间里会出现他的化身，按对方房间自己的布局走过去、拿起同一张、放到对应的位置。

中间的翻译由电脑上的中转完成。两个房间只把"布局"和"动作"写成文字发给中转，中转用 OpenAI 判断两边哪块面板对应哪块，把动作改写成对方房间的说法，再读一读这个人的拿放过程，猜他在想什么（犹豫、换组、按什么分类），把解读作为字幕发给对方。

任务取自 Syiem et al. (2024, IJHCS) 用的 Stanford & Stanford 谋杀谜题，这里只放了 6 张便利贴和 2 个分组。

## 日常使用

两台头显上的应用装好以后，平时不用连 USB，也不用重新打包：

1. 电脑连上和头显相同的 Wi-Fi，启动中转：苹果电脑双击 `Start-Relay-Mac.command`，Windows 电脑双击 `03-Start-Relay-For-Quest.cmd`。窗口要一直开着。
2. 头显开机，在应用库的"未知来源"里打开应用：

| 头显序列号 | 应用 | 布局 |
| --- | --- | --- |
| Marvin‘s | `Mystery Sort MR A` | 墙面，三块竖直面板 |
| zhanna's| `Mystery Sort MR B` | 桌面，三块水平垫子 |


3. 状态栏出现 `Relay 192.168.x.x` 就是连上了。

完整步骤、第一次在新房间布置、苹果电脑的防火墙设置和连不上时的排查，见 [日常启动.md](日常启动.md)。手柄和手势的具体操作见 [Quest-APK/使用说明.md](Quest-APK/使用说明.md)。

**第一次在新电脑上用中转**：OpenAI 密钥不在仓库里。在 `relay/` 里把 `.env.example` 复制成 `.env`，填入 `OPENAI_API_KEY`。没有密钥中转也能跑，只是面板按编号对应，字幕没有 AI 解读。

## 怎么工作

```
 房间 A 头显  ──UDP──▶  电脑上的中转  ──UDP──▶  房间 B 头显
 （墙面）    ◀──────  relay/relay.py  ◀──────  （桌面）
                          │
                          └── OpenAI：面板对应、动作改写、意图解读
```

**每个房间发给中转的**

- **布局文字**（每秒一次）：每块面板叫什么、竖着还是躺在桌上、在人的哪个方向、多远，以及六张便利贴的线索内容。
- **完整状态**（每秒 20 次）：每张便利贴在哪块面板上、手里拿着哪张、悬停在哪块面板上、在看哪张，外加最近几次动作的句子（"拿起 E"、"把 E 放到 Group 1"）。发完整状态而不是单次事件，丢一个包也不会让两边不一致。
- **运动轨迹**（每 0.4 秒一行）：手里的便利贴离每块面板多远、往哪块移动、多快。轨迹里不写"犹豫"这种判断，留给模型自己读。

**中转做的**

1. 两边的布局文字都到了以后，让模型决定 A 的哪块面板对应 B 的哪块（功能相同优先，其次是相对人的方向）。
2. 把一边的状态改写成另一边的面板编号再转发。
3. 把动作句子换成对方的面板名，作为字幕发给对方。
4. 每次放下便利贴后，以及拿着便利贴期间每约 2.4 秒，把整个过程（动作、最近 12 秒的轨迹、当前分组、上一次的解读）发给模型，要求返回 JSON：状态（exploring / deciding / confident / revising）、置信度、一句解读、正在哪几块面板之间犹豫、每组的标签、预测下一张。解读作为字幕发给对方；如果模型认为这个人在两块面板之间犹豫，对方房间的化身会站到两块面板之间来回看。

**两个人同时操作时**

每张便利贴带一个版本号，每放下一次加一。两边先后把同一张放到不同面板，后放的生效，另一边的化身会去把它挪过来。对方手里拿着的、或者本房间化身正在搬的便利贴不能拿。两人同一瞬间拿同一张，B 松手。

**用人的走动藏延时**

化身要走路，所以总比真人慢几秒。头显里不能隔空点选便利贴，必须走过去用手捏（或把手柄伸到便利贴上扣扳机）。人走过去的这几秒，对方的化身也在走。B 的桌面布局走动少，所以 B 的动作传到 A 时延时更明显。

**面板固定在真实房间里**

混合现实版用 Meta 的空间锚点：每块面板放下时在真实房间里钉一个锚点，存在这台头显上。以后每次打开，面板直接回到墙上或桌上的原位，不需要站固定位置或重新定位。A 的面板锁定竖直，B 的垫子锁定水平。

## 仓库结构

| 路径 | 内容 |
| --- | --- |
| `Unity/` | 桌面版 Unity 工程，鼠标操作，用于在一台电脑上预览和自动测试 |
| `UnityQuest/` | 头显版 Unity 工程，打包四个 Quest APK |
| `Unity/Assets/Scripts/` | 两个工程共用的脚本（改完要复制到 `UnityQuest/Assets/Scripts/`） |
| `relay/relay.py` | 中转，只用 Python 标准库 |
| `Quest-APK/` | 安装脚本和头显使用说明（APK 本身不在仓库里） |
| `Start-Relay-Mac.command`、`03-Start-Relay-For-Quest.cmd` | 给头显用的中转启动脚本 |
| `01-Preview-With-AI-Relay.cmd`、`02-Preview-Direct.cmd` | 在一台 Windows 电脑上同时开 A、B 两个窗口预览 |

主要脚本：

- `SortDemo.cs`：布局、拿放输入（鼠标、手柄、手势捏合）、把动作和布局写成文字、化身该做什么、空间锚点。
- `AvatarActor.cs`：化身走路（Mixamo 的 Idle/Walking 混合）、转头看目标、右臂两段骨骼 IK 伸手拿放。
- `SortProtocol.cs`：UDP 收发、序号去重、超时。
- `RelayDiscovery.cs`：头显收听中转的广播，自动找到电脑的地址。

## 开发环境

- Unity **6000.0.46f1**，Android 打包模块
- Meta XR Core SDK 74.0.2，Unity OpenXR 1.14
- 化身：Rocketbox Female_Adult_01；动画：Mixamo Idle、Walking
- 中转：Python 3，不需要额外安装库
- 头显：Quest Pro（Quest 3 应该也能用，没测过）

**打包**：用 Unity 打开 `UnityQuest`，菜单 `Mystery Sort / Build Quest A and B (MR passthrough)` 生成 MR A、MR B 两个 APK 到 `Quest-APK/`。VR 版用 `Build Quest A and B (VR)`。场景由脚本生成，面板位置和便利贴内容写在 `SortDemo.cs` 的 `BuildRoom` 和文件开头的数组里，在编辑器里拖物体不会生效。

**克隆后第一次打开**：仓库不含 `Library/` 和 Mixamo 的源 FBX。Unity 会重新导入一遍（比较久），并且要自己把 Mixamo 的 Idle 和 Walking 放回 `Assets/MixamoAnim/`。

**桌面预览**：Windows 上双击 `01-Preview-With-AI-Relay.cmd`，会打开中转和 A、B 两个窗口，按住鼠标左键拖便利贴。这个中转只接受本机，实验室里开着的头显不会连上来。

## 网络

| 端口 | 谁在听 | 用途 |
| --- | --- | --- |
| UDP 9000 | 电脑（中转） | 两个房间的状态、布局、轨迹都发到这里，中转再转发给另一边 |
| UDP 9001 | 头显 | 中转每秒广播一次"我在这"，头显据此找到电脑 |

9002 是早期单向版本里 B 的接收端口，现在的版本不再用它。

头显里没有写死任何 IP，中转从收到的包里记下两台头显的地址。三台设备必须在同一个 Wi-Fi 的同一个网段，广播过不了路由器；隔离设备间通信的校园网、访客网用不了。目前用的是 yihao 的 Wi-Fi（实验室的 `aid-lab_IoT_2.5G`）。

通信没有加密和身份验证，只适合在实验室自己的网络里用。

## 现状

**已验证**

- 桌面版在一台电脑上自动跑通：A 归 3 张（其中一张故意犹豫），B 再放 1 张，两边最终摆放一致，模型对两边都给出了解读，犹豫被识别并由化身演出来。
- 两台 Quest Pro 通过实验室 Wi-Fi 找到中转并互相同步；透视、锚点权限在头显上确认开启。

**没验证或已知问题**

- 延时：化身比真人慢几秒，目前靠"必须走过去捏"来掩盖，B 的桌面一侧掩盖得不够。后续再看怎么处理。
- 空间锚点重启后能否回到原位、灯光变化后能否认出房间，还需要在实验室实测。
- 化身不避让人和家具，走直线。
- 化身在桌子对面伸手的距离是估的，可能够不着或伸进桌子里。
- 模型给的置信度普遍偏高；意图解读只在一条脚本轨迹上检查过。
- 面板对应只在中转启动后算一次。如果当时头显没人戴，左右可能对调（同步不受影响）。

## 备注

- OpenAI 用的是 Anusha 的 API 密钥。密钥没有写进代码，只放在中转电脑的 `relay/.env` 里，不进仓库，也不装进头显；换电脑要重新放一份。
- 原来的单向版本（A 操作、B 只看）在提交历史里，`2c8d1be` 及更早。
